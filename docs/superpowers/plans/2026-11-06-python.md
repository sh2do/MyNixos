# The Python Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the cobra with a reticulated python that spiral-wraps the niri bottom bar, three coils in front of and behind the pill, with its head rising off the right end. It's tinted from the wallpaper and lightly animated. A matching coiled-ball python becomes the fastfetch logo.

**Architecture:**
- **Geometry** (where the coils go, given the pill's size and the gaps between widget groups) is a pure JavaScript library, `python-geometry.js`, tested with node.
- **Drawing:** `Python.qml` draws one body path as layered stroked `ShapePath`s (outline, body, saddles, flecks, highlight) twice: a back layer under the pill, masked by the pill's shape, and a front layer over it, clipped to the crossings.
- **Animation:** one slow timer drives all of it, like `Cobra.qml` does today.

**Tech Stack:** Quickshell 0.3.2 (QML, QtQuick.Shapes, QtQuick.Effects), matugen 4, rsvg-convert, node (only for tests, via `nix run nixpkgs#nodejs`).

**Spec:** `docs/superpowers/specs/2026-11-06-python-design.md`

## Global Constraints

- Body thickness is about 40% of the pill height, so `bodyWidth = Math.round(Theme.barHeight * 0.4)`, which is 15 px.
- The pill's resting gap above the screen edge goes from 8 px to `8 + bodyWidth + 1`, about 24 px. The 3 px reveal strip stays. The pill's height stays `Theme.barHeight` (38).
- Colours:
  - outline and base: `Theme.surface`
  - body: `Theme.surfaceContainer`
  - saddles: `Theme.primaryContainer`
  - flecks and eyes: `Theme.tertiary`
  - head: `Theme.secondary`
  - Add any of these that `Theme.qml` lacks, reading from `colors.json` the same way the existing ones do.
- Front crossings never overlap a widget's rectangle. Back coils never show through the pill.
- With the bar hidden for 60 s, `top -b -n 3 -p $(pgrep -f 'qs -c rice')` averages under 1% CPU. The single timer runs at most 25 fps and stops while `running` is false.
- `modules/shell/default.nix` ships only `.qml` and `.svg` today. Add `.js` to its filter.
- `git add` before `nix build`. The user switches with `! nh os switch`. Never run sudo.

## Review Focus

1. **Bar width changing at runtime** (a bluetooth toggle appears, workspaces are added): the coils must re-lay out without overlapping widgets. Test `test_crossings_avoid_widgets_for_any_gap_set` in Task 1.
2. **Very few gaps** (only two widget groups): fewer than three crossings must still draw a sane spiral, not throw. Test `test_two_gaps_gives_two_crossings` in Task 1.
3. **Clicks pass through to the widgets under the coils' surface area**, and still reach the bar's widgets. The mask region covers the pill plus the drawn coils, never the whole surface. Task 2 step 5 checks clicks on every widget.
4. **Fullscreen windows:** the bar is on the Top layer and fullscreen covers it today. The coils must hide with it. Task 2 step 5 checks this.
5. **Wallpaper change while the bar is shown** recolours the python live with no QML errors. Task 2 step 5.

### Task 1: Coil geometry

**Files:**
- Create: `modules/shell/python-geometry.js` (`.pragma library`)
- Create: `tests/python-geometry-test.js` (node; loads the library with `vm` after stripping the `.pragma library` line)
- Modify: `modules/shell/default.nix` (filter also ships `.js`)

**Interfaces:**
- Produces `layout(pillW, pillH, gaps, bodyW)`. All coordinates are in the pill's own frame: x from 0 to `pillW`, y from 0 to `pillH`, negative y is above the pill.
  - `gaps`: an array of `{x, w}`, the free horizontal spans inside the pill between widget groups, sorted by x.
  - Returns `{ path, crossings, head, bounds }`:
    - `path`: an array of cubic segments `{x0,y0,c1x,c1y,c2x,c2y,x1,y1}`, from the tail to the neck.
    - `crossings`: an array of `{x0, x1}`, the horizontal spans where the body passes in front of the pill.
    - `head`: `{x, y, angle}`, where the angle is in degrees and 0 points +x.
    - `bounds`: `{x, y, w, h}`, the box around everything drawn, including the head.
- Produces `pickGaps(gaps, n)`: chooses up to `n` crossing gaps, widest first, returned sorted by x.

- [ ] **Step 1:** Write `tests/python-geometry-test.js` using plain `assert`. The tests:
  - **`test_three_crossings_in_widest_gaps`:** with `pillW = 400`, `pillH = 38`, `bodyW = 15` and gaps `[{x:6,w:30},{x:120,w:24},{x:260,w:40},{x:350,w:28}]`, `crossings.length === 3`. Each crossing lies inside one of the three widest gaps: `x0 >= gap.x` and `x1 <= gap.x + gap.w`.
  - **`test_crossings_avoid_widgets_for_any_gap_set`:** for 200 random gap sets, each a sorted, non-overlapping set of 2 to 6 gaps between 18 and 60 px wide inside `pillW` from 250 to 600, every crossing sits inside some gap.
  - **`test_two_gaps_gives_two_crossings`:** two gaps give `crossings.length === 2` and don't throw.
  - **`test_tail_left_head_right`:** `path[0].x0 < 0` (the tail starts off the left end), `head.x > pillW` and `head.y < 0` (the head rises off the right end, above the pill).
  - **`test_lower_loops_fit_raised_gap`:** the body's lowest point (max y over the path, plus `bodyW/2`) is at most `pillH + bodyW + 1`. The loops must fit into the raised gap.
  - **`test_bounds_cover_head`:** `bounds` contains `head.x ± 20` and `head.y ± 20`.
- [ ] **Step 2:** Run `nix run nixpkgs#nodejs -- tests/python-geometry-test.js`. Expected: FAIL (file missing).
- [ ] **Step 3:** Implement `layout` and `pickGaps`. Each front crossing is a diagonal from the pill's top edge (y = -bodyW/2) to its bottom edge (y = pillH + bodyW/2) within its gap. Each back segment loops from the bottom of one crossing, under and behind, to the top of the next. Use the mockup's curve shapes as a guide (`python-pose.html`, option C).
- [ ] **Step 4:** Run the tests. Expected: all PASS.

### Task 2: Draw the python on the bar

**Interfaces:**
- Consumes `layout` and `pickGaps` from Task 1, imported in QML as `import "python-geometry.js" as Geo`.
- Produces `Python.qml` with these properties:
  - `pill: Item` (the bar rectangle)
  - `gaps: var` (the array of `{x,w}`)
  - `layer: string` (`"back"` or `"front"`)
  - `running: bool`
  - `t: real` (animation clock in ms; it's driven by the front instance and bound into the back one, so both stay in sync)
  - `hoverX: real` (the pointer's x in pill coordinates, or `NaN`)

  Task 3 animates through `t` and `hoverX`.

- [ ] **Step 1:** Write `Python.qml`. It's a `Shape` whose `ShapePath`s all share a path built from `Geo.layout(...)`:
  - **Base:** stroke `Theme.surface`, width `bodyW + 4`, round caps.
  - **Body:** `Theme.surfaceContainer`, width `bodyW`.
  - **Saddles:** `Theme.primaryContainer`, width `bodyW - 4`, `DashLine` with the pattern `[0.73, 0.4]` in stroke-width units. The pattern must still read as irregular diamonds; tune it visually.
  - **Flecks:** `Theme.tertiary`, width about 4, dash `[0.6, 3.6]`, offset into the saddle gaps.
  - **Highlight:** white at 12% opacity, width 2, offset up 3 px.

  For `layer: "back"`, mask out the pill's rounded rectangle with a `MultiEffect` mask, or an inverted `OpacityMask` equivalent. For `"front"`, clip to the `crossings` spans.

  The head is drawn as an `Item` at `head.x`/`head.y`, rotated by `head.angle`, in the front layer only:
  - a gold-wedge `Shape` in `Theme.secondary` with a dark crown line (`Theme.surface`)
  - two `Theme.tertiary` eyes
  - a forked tongue in `Theme.tertiary`, hidden at rest

### Task 3: Animation

**Files:**
- Modify: `modules/shell/Python.qml`, `modules/shell/BottomBar.qml` (pass `running: root.shown` and `hoverX` from a `HoverHandler` on `bar`)

**Interfaces:**
- Consumes `t`, `hoverX` and `running` from Task 2.

- [ ] **Step 1:** Add one `Timer` (40 ms, `running: root.running`) that advances `t`, like `Cobra.qml` did. Derive everything from `t`:
  - **Breathing:** the coil amplitude is scaled by `1 + 0.02 * sin(2πt/5000)` (pass an amplitude factor into `Geo.layout`).
  - **Sliding:** every 20–40 s (randomised), the saddle and fleck `dashOffset` advances by one pattern length over 1 s with ease-in-out.
  - **Tongue:** a flick every 8–15 s, out and back over 300 ms, reusing the cobra's `flickPhase` formula.
  - **Hover tracking:** while `hoverX` isn't NaN, the head angle eases (over about 300 ms) toward the angle pointing at `(hoverX, pillH/2)`, clamped to ±35° from its rest angle. It eases back when the pointer leaves.
- [ ] **Step 2:** Run `RICE_BAR_PINNED=1 qs -p modules/shell` and watch for 60 s. Expected: all four motions happen, and the slide and the tongue each happen at least once.
- [ ] **Step 3:** CPU check. With the bar hidden for 60 s, `top -b -n 3 -p $(pgrep -f 'qs -c rice')` averages under 1%. With the bar shown, note the figure in the commit message.
